# 4char-captcha-onnx

一个 **4 字符图形验证码**的 ONNX 识别模型。输入一张验证码图片，输出 4 个字符，附带 4 个头各自的判断，用来判断这次结果可不可信。

单文件 25.6 MB，纯 CPU 单张约 4 ms，不需要 GPU。

> **下载**：模型文件 25.6 MB，超过 GitHub 网页上传限制，因此不在仓库里。
> 请到本仓库的 [Releases](../../releases) 页面下载 `captcha_model.onnx`（或含模型的完整 zip），
> 放到本目录下即可直接运行 `demo.py`。

## 模型规格

| 项 | 值 |
|---|---|
| 输入 | `input1`，float32 `[1, 1, 64, W]`（灰度、高固定 64、宽可变） |
| 输出 | `ens`（集成）、`h0`~`h3`（4 个头） |
| 中间输出 | `380`、`227`、`feat1536`（调试用，可不取） |
| 字符集 | 32 类，CTC blank 为索引 0（见 `charset.json`） |
| 解码 | CTC 贪心（合并相邻重复 → 去 blank） |
| 体积 | 25.6 MB |

## 快速开始

```bash
pip install onnxruntime numpy pillow
python demo.py 你的图.png
```

```
你的图.png   -> 23KX   4/4  ACCEPT
```

`demo.py` 只有 100 行，没有任何私有依赖，可以直接抄进你自己的工程。

## 输入要求（重要）

预处理必须和训练时一致，否则精度会明显掉：

1. 转灰度（`Image.convert("L")`）
2. **按比例**缩放到高 64，宽度 = `round(原宽 × 64 / 原高)`，算法用 **LANCZOS**
3. 归一化 `/ 255.0`
4. 形状 `[1, 1, 64, W]`

**这个模型是在"屏幕截图"的输入上训练的**——图像已经经过了渲染放大，不是接口返回的原始小图。直接喂未放大的原图会明显掉点（实测约 10 个百分点）。

如果你的图是未经放大的原始小图，建议先用 `BILINEAR` 放到约 1.25 倍再送进去，更接近训练分布。

## 输出怎么用

`ens` 是 4 个头 log-softmax 的平均，`h0`~`h3` 是各自的结果。建议的判定：

```
先按 ens 解码出文本
再让 4 个头各自解码
票数 = 4 个头里与 ens 完全一致的个数

放行条件：文本正好 4 个字符 且 票数 == 4
```

**别省略这一步。** 模型的错误高度集中在"票数不足"的那批图里，闸门拦下来的才是安全的。实测：

| 指标 | 数值 |
|---|---|
| 放行率 | 92.2% |
| 放行里答对 | **99.7%** |
| 错提（放行了但答错） | 0.27% |

反过来说：**没通过闸门的图直接换一张，成本几乎为零；放行错了才是真的损失。** 这个模型的用法是"少做但做对"，不是"全都猜"。

## 精度

在自建的 744 张真实截屏上（其中 670 张参与过训练）：

| 口径 | 裸对 |
|---|---|
| 全部 744 张 | 95.0% |
| 未参与训练的 74 张（多为模糊/低对比的难例） | 62.2% |
| 合成渲染图 8068 张（未参与训练部分） | ≈100% |

诚实说明：合成图和真实截屏之间有明显 domain gap，**合成图的高分不能代表真实效果**。真实场景请以你自己的数据为准。

## 字符集覆盖

`charset.json` 里列了 32 个字符，但训练数据里只出现过 27 个：

- 从未出现：`9` `1` `S` `L` `O`
- 出现个位数：`Z`（3 次）、`B`（3 次）

遇到含这些字符的图，模型基本靠猜。如果你的场景里它们常见，这个模型不适合你。

## 训练与来源

- 骨干网络来自 [sml2h3/dddd_trainer](https://github.com/sml2h3/dddd_trainer)（Apache-2.0）。本项目**冻结**其卷积+BiLSTM 部分，只取 `feat1536` 作为特征。
- 在冻结特征上训练了 4 个独立的分类头（每头 1536→256→33），用不同随机种子训练后取 4 个组成集成。
- 训练数据：真实屏幕截屏 + 合成的同分布渲染图。

改动说明：原骨干输出的是 CTC 序列，本项目只保留其特征，另接 4 头；同时删除了推理不需要的节点（57.7 MB → 25.6 MB，逐张输出完全一致）。

## 已知限制

- **只支持 4 字符**。3 个或 5 个字符的验证码不适用。
- **不做检测和切图**。输入必须是已经裁好的、只含验证码的图。
- **对缩放敏感**。预处理和上面写的不一致就会掉点。
- **不是通用 OCR**。只认识这 32 个字符，中文、符号一概不认识。
